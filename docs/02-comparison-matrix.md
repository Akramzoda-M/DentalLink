# Сравнительная матрица аналогов: ИС «Онлайн-запись в стоматологию» (DentalLink)

**Проект:** DentalLink — ИС «Онлайн-запись в стоматологическую клинику»  
**Дата проверки:** 10.11.2026  

---

## 1. Аналоги

Для анализа выбраны 3 системы разного типа: федеральный медицинский агрегатор, специализированная облачная МИС для стоматологий и локальный ручной процесс (наиболее распространённый конкурент в региональных клиниках):

1. **СберЗдоровье / ПроДокторов** (Крупный федеральный медицинский агрегатор) — [https://sberhealth.ru](https://sberhealth.ru) / [https://prodoctorov.ru](https://prodoctorov.ru) (Проверено: 10.11.2026)
2. **IDENT / Medesk** (Специализированная медицинская информационная система (МИС) для стоматологий с модулем онлайн-расписания) — [https://ident-med.ru](https://ident-med.ru) / [https://www.medesk.ru](https://www.medesk.ru) (Проверено: 10.11.2026)
3. **Локальный ручной процесс клиники** (приём звонков администратором, запись в бумажный журнал или таблицу Excel, ручная переписка в мессенджерах) — представляет текущее состояние процессов в большинстве небольших стоматологий. (Проверено: 10.11.2026)

- **0 баллов:** Функция отсутствует или реализована критически неудобно (требует звонка, долгого ожидания, ручной обработки).
- **1 балл:** Функция реализована частично, есть заметные задержки или функциональные ограничения.
- **2 балла:** Функция реализована полностью в реальном времени, интуитивно понятна и удобна для пользователя.

## 4. Измерения

- **Скорость загрузки (PageSpeed Insights, Desktop):**
  - **СберЗдоровье / ПроДокторов:** ~62–70 баллов (тяжёлые бандлы JavaScript, маркетинговые трекеры, скрипты геолокации и сторонние виджеты).
  - **IDENT / Medesk (клиентские виджеты):** ~65–75 баллов (iframe-вставки виджетов замедляют загрузку основной страницы сайта клиники).
  - **DentalLink (целевой показатель на React SPA: Vite + Tailwind CSS):** ≥ 85 баллов по PageSpeed Desktop за счёт сборки Vite, разделения кода по маршрутам и отсутствия рекламных скриптов. Серверный рендеринг не используется: данные расписания запрашиваются у ASP.NET Core API.
- **Интерфейсные сценарии:**
  - Время записи пациента через агрегаторы: ~3–4 минуты (поиск клиники, выбор врача, ввод подтверждающих кодов, фильтры).
  - Время записи через DentalLink: ≤ 1 минуты (прямой выбор специалиста клиники, свободного окна и ввод номера телефона).

## 5. Выводы и проектные решения

На основе анализа матрицы аналогов для системы **DentalLink** приняты следующие архитектурные и продуктовые решения:

### Заимствуем (3 решения):
1. **Интерактивная сетка расписания (Timeline)** *(Критерий 4)*: Как в специализированных МИС (IDENT), реализуем наглядную сетку времени по кабинетам и креслам для администратора клиники с цветовой индикацией статусов приёма.
2. **Временное удержание слота (Slot Hold)** *(Критерий 2)*: Когда пациент выбирает слот, система на 10 минут переводит его в `reserved` и ставит блокировку в Redis. Повторная запись на этот слот отклоняется, пока удержание действует или пока транзакция бронирования не закрепит его как `booked`.
3. **Двухэтапная цепочка напоминаний** *(Критерий 3)*: Напоминания за 24 часа и за 2 часа до приёма с интерактивными кнопками («Подтверждаю» / «Прошу перенести»), что снижает процент неявок (No-Show) минимум на 70%.

### Не делаем (1 решение):
- **Сложная электронная медицинская карта (ЭМК) и заполнение зубной формулы в MVP** *(Критерий 8)*: Полнофункциональные МИС перегружены медицинскими справочниками МКБ-10, рентген-снимками и финансовой бухгалтерией. В MVP DentalLink фокус держится исключительно на идеальном процессе записи, расписания и коммуникации с пациентом, чтобы система оставалась лёгкой, быстрой и недорогой.

### Наше отличие (2 решения):
1. **Бесплатные интерактивные напоминания через Telegram Bot** *(Критерий 3)*: В отличие от тяжелых МИС, где клиника платит за каждое SMS, DentalLink отправляет интерактивные уведомления через официальный Telegram Bot API с кнопками мгновенного подтверждения прямо из мессенджера.
2. **Запись без пароля** *(Критерий 6 и 5)*: пациент указывает имя и номер телефона и не получает учётную запись. Свои визиты он открывает по этому же номеру. Telegram используется только для уведомлений. Клиент на React (Vite) и API на ASP.NET Core 10 должны открывать страницу записи с LCP не хуже 1,2 секунды на обычном канале (НФТ-01).
